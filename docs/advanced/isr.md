您可以在后台的 `系统设置/高级设置` 中更改静态页面更新策略或者强制触发静态页面更新：

![更新策略设置](https://pic.mereith.com/img/7bb50e93e1ef869b6117cd88c92ebb72.clipboard-2023-02-01.png)

### 静态页面更新策略

有两种：延时自动、按需自动

- 延时自动： 使用 Next.js 内置的静态增量再生，可以设置重新尝试生成静态页面的时间。实时性略低。
- 按需自动： 每当后台有数据更改时，按需触发静态渲染。实时性高，可能需要更多性能。文章会同时刷新数字 ID 地址（`/post/<id>`）和自定义路径地址（`/post/<pathname>`），搜索结果跳到数字 ID 时也能看到最新内容。

### 强制触发静态页面更新

点此按钮可强制触发静态页面的渲染更新，无论设置何种更新策略。

若源站（直连容器端口）已经是新内容，公网反代或 CDN 后面仍是旧文章，请检查外层是否在缓存 HTML，见 [后台发布后前台不刷新仍显示旧文章](../faq/deploy.md#后台发布后前台不刷新仍显示旧文章)（[#469](https://github.com/Mereithhh/vanblog/issues/469)）。

### 几个内建的兜底（2026-09 起）

- **延时秒数有 60 秒下限**：延时自动模式里填的值（前台的 `VAN_BLOG_REVALIDATE_TIME`）低于 60
  会被抬到 60，非法/空值也回落 60。以前的 10 秒意味着有流量时每页每 10 秒重渲染一轮
  （本站一轮 ~130 个路由，每次都要回调 server 的公开接口），而「改完 1 分钟内可见」对个人博客完全够用。
- **按需模式也有 24 小时长保险**：按需生成的页面以前永不过期，全靠 server 的触发；
  万一某次触发丢了（前台容器正在重启、网络抖动），页面会一直停在旧内容上。现在按需模式
  也带 24 小时的 revalidate，最坏从「永久陈旧」变成「最多陈旧一天」。
- **失效产物清理器**：主进程默认每 15 分钟对账一次（`VANBLOG_ISR_REAP_INTERVAL_MS`），
  删掉「库里已不可见但磁盘上还留着」的静态 HTML —— 删除、隐藏、加密、未到点的定时文章都算。
  这也是 caddy 直发 HTML（`VANBLOG_CADDY_SERVE_HTML`，默认关；`all` 模式覆盖文章页等动态路由，
  要求 ISR 是按需模式）敢于存在的前提：直发是按文件发的，磁盘上留着什么就发什么。
  清理器与该开关**解耦**，直发关着也照跑。实测数字见 [性能实测](./benchmark.md)。
- **静态搜索索引跟着同一条触发链走**：每次全量渲染（保存文章、手动触发、每小时兜底 cron）
  会顺带重建 `/static/search/index.json`，见 [文章搜索](../features/search.md)。

VanBlog 内置了 `RSS feed 生成器` ，开箱即用。

<!-- more -->

## 简介

你可以从站点的以下地址获取 RSS:

- `<your-site-url>/feed.xml`: RSS 2.0 格式
- `<your-site-url>/feed.json`: JSON 1.1 格式
- `<your-site-url>/atom.xml`: Atom 1.0 格式

这三个短地址由 caddy 改写到 `/rss/...`（`/feed.xml → /rss/feed.xml`、`/atom.xml → /rss/atom.xml`、
`/feed.json → /rss/feed.json`），直接访问 `/rss/` 下的原始地址也一样。

导航栏右上角会默认出现 `RSS` 按钮。您可以在后台的 `布局设置` 中关闭此按钮。

VanBlog 包含后端 Markdown 渲染器，因此你可以在支持 HTML 内容的 RSS 阅读器上获得与网页相近的体验。

::: tip 刚发布的文章不会立刻出现在 feed 里（最多等 3 分钟）

feed 是 server 生成的静态文件，改动后有 **3 分钟防抖**。这是故意的：以前不设条数上限时，
几十篇文章的全站渲染就要 **135ms 同步阻塞事件循环**、三份 feed 各约 350KB，而这件事每小时兜底跑一次、
每次启动跑一次 —— 文章只会越来越多，所以既加了防抖，也把默认条数限到最新 50 条
（`VANBLOG_RSS_ITEM_LIMIT`，设成 0 就是全量）。

实测：新建一篇文章后 60 秒内 `static/rss/` 还是空目录、`/feed.xml` 回 404，**3 分钟后**才出现。

⚠️ 别把它和另外两个产物搞混：**sitemap 与搜索索引的防抖是 60 秒**，只有 RSS 是 3 分钟。
所以「已经搜得到、feed 里却还没有」是正常的，不是 RSS 坏了。

:::

## 正文的 HTML 过滤

feed 里的正文与摘要是**过滤后**的 HTML。文章正文允许写原始 HTML，而这些内容会**从你自己的域名**发出去
（`/rss/*` 由 server 直服，降级期还会被 caddy 直发磁盘产物），所以 RSS 这条出口与前台文章页用**同一套白名单**：
前台走编辑器管线里的 `rehype-sanitize`，RSS 走服务端的镜像实现，两边由跨包一致性测试钉住不漂移。

::: tip 这是"作者内容"的边界，不是"防评论灌水"

管理员本来就是可信作者 —— 站点级的 JS/HTML 有 `定制化` 那条正规通道，不需要塞进正文。
⚠️ 但"可信"**不包括只有文章写权限的协作者**（`article:create` / `article:update`）：
他们写的正文会渲染给每一个访客，所以这道白名单是**真实的边界**，不是形式。

:::

- **会被移除**：`<script>` 与 `<style>` 元素**整段消失（连内容一起）**；`onclick` / `onerror` 这类事件属性；
  `javascript:` 与非 http(s) 的 URL；`<a>` / `<input>` / `<button>` 上的内联 `style`
  （排版类标签上的 `style` 保留）；以及 **HTML 注释**（包括 `<!-- more -->`）。
- **会被改写**：实体与属性引号会被规范化（`&amp;` → `&#x26;`、`src=x` → `src="x"`）。
  ⚠️ **字符与语义都不变**，只是序列化形式变了。
- **`<iframe>` 保留**，但 `src` 只允许 http(s) 与协议相对写法（`//host/...`）。
- 🔴 **公式的 MathML 会保留**：`<math>` / `<semantics>` / `<mrow>` / `<annotation>` 等 19 个标签，
  属性按**值白名单**逐个校验（不是"给了名字就什么值都收"）。

  ⚠️ 这一条曾经不是这样。早期版本把 MathML 整组丢弃，而 `.katex-mathml` **没有** `aria-hidden`
  （读屏器读的正是它），丢弃后其子节点会塌成**乱码重复文本**（`$E=mc^2$` → `E=mc2E=mc^2`）——
  也就是说旧行为不是"少了读屏支持"，而是**给读屏器喂垃圾**。现在保留完整 MathML（含 `annotation` 里的 LaTeX 源）。

  ⚠️ **前台文章页从来没有这个问题**，原因是两条管线里 katex 与过滤的先后顺序不同：
  前台是"先过滤、再由 katex 插件产出"，MathML 生成于过滤之后；RSS 是"先渲染成 HTML 字符串、再过滤"。
- 🔴 **两个第三方样式表带 SRI**：katex 与 highlight.js 的 CSS 从 CDN 引入，都带 `integrity`（sha384）
  与 `crossorigin="anonymous"`。⚠️ 它防的是 CDN 被劫持时的**界面重绘 / 遮罩钓鱼**，
  以及用属性选择器 + `background: url()` 把内容外泄到攻击者域名 ——
  **CSS 本身不执行 JS**，所以别把它理解成"能跑任意脚本"。
- ⚠️ **你自己站点的那份 `markdown.css` 不带 SRI**：它随每次部署变化，钉住哈希会让它每次发版都失效。

::: note 已知局限（有意不修）

- `<div style="position: fixed; inset: 0; z-index: 9999">` 这类**整页遮罩**拦不住：
  `div` / `span` / `p` 是正常排版必需的标签，要拦只能去过滤 `style` 的**值**，那会误伤正常排版。
  ⚠️ 不过最短的那条点击劫持路径已经堵住 —— `<a>` 上的内联 `style` 是被摘掉的。
- 同一条理由，`style` 值里的 `url(javascript:...)` 也拦不住。

:::

::: tip 对现有文章的影响：实测零破坏

用一份 **53 篇真实文章**的站点全量比对过：

- 含原始 HTML 的只有 **7 篇**；用到的标签是 `font`(64) / `br`(27) / `h1`(5) / `o`(1，Word 粘贴残留) / `img`(1)，
  属性只有 `style`(64，**全部是 `color`**) / `id`(5) / `height`(1) / `src`(1)。
- 危险构造（`expression(`、`behavior:`、`-moz-binding`、`javascript:`、`onerror`、`onclick`、`onload`、`<script`）
  与 `<iframe>` **全部 0 处** ⇒ 白名单没有删掉任何真实内容。
- 正文总字节 189,017 → 178,477（**−5.58%**），变化全部落在四类里、**没有一类丢正文**：
  HTML 注释被删（`<!-- more -->` 恰好 13 字节，所以多数文章正好少 13）、实体重编码、属性引号规范化、MathML 曾被丢弃。
- 保留 MathML 并加上 SRI 之后，整个 `atom.xml` 从 294,361 B 变成 **306,264 B（+4.0%）**。

⚠️ 唯一肉眼可见的差别是**正文里的 `<!-- more -->` 注释不见了** —— 它本来就不该出现在输出里；
摘要的截断口径见下文「信息生成 → 摘要」。

:::

## 信息生成

- 作者: RSS 订阅中的作者邮箱优先取自 `评论设置` 中的作者邮箱，其次是启动 VanBlog 时传递的 `EMAIL` 环境变量。

- 图标:

  订阅中的 `favicon` 和 `images` 属性的优先级如下：

  ![图标/图片优先级](https://www.mereith.com/static/img/27f6636bfe5a53cf51544ab8affd6961.clipboard-2022-09-04.png)

- 摘要

  订阅中每篇文章的 `description` 字段取自文章摘要，与前台列表**同一个口径**，分三种情形：

  - **有 `<!-- more -->` 且标记在 400 字以内** → 摘要就是**标记之前的那一段**（作者的编辑意图完整保留）；
  - 🔴 **有标记但标记在 400 字之后** → 摘要**截到 400 字**（2026-09-22 起新增的硬上限，见下）；
  - **没有标记** → 取**前 200 字**（不是全文）。

  全文在 `content:encoded` 里，阅读器照样能拿到完整正文。

  ⚠️ 截断点如果落在 `[文字](链接)` 中间，会把整个链接补全再截（否则会露出裸括号和半个链接），
  emoji 也不会被切成两半 —— 所以摘要**偶尔略多于上面那个字数**是正常行为，不是 bug。

  🔴 **关于那个 400 字硬上限（2026-09-22 起，属默认行为变更）**：此前**只要有 `<!-- more -->`，
  字数预算就完全不参与** —— 摘要就是标记之前的全部内容。于是作者把标记放得很晚
  （或导入工具批量在文末追加标记）时，**列表页与 RSS 摘要会下发整篇正文**，
  而这部分内容对匿名读者是**无需认证、可反复拉取**的。现在标记位置超过 **400 字符**时会被截断
  （截断仍复用上面那套"补全被截断的行内链接、不切开 emoji"的逻辑）。
  ⚠️ **400 字以内的标记位置不受任何影响**，所以正常写作的摘要形状不变。
  ⚠️ 这个上限是**代码里的常量、不是环境变量**，而且是**有意的**：前台那份摘要实现跑在**浏览器**里
  （文章卡片组件用了 `useMemo`/`useState`），读不到 `process.env.VANBLOG_*`；
  一侧可配一侧不可配会让两边在生产环境算出**不同**的摘要，表现为卡片文字在 ISR 重渲染前后跳变。
  ⚠️ 订阅源是落在磁盘上的静态文件、由服务端定期重写，所以**上限在下次重新生成 feed 时才生效**。
  🔴 **文章详情页与全文渲染完全不受影响**（走的是另一条路径）。

  > 以前的实现是"没有 `<!-- more -->` 就把全文塞进 `description`"，而且会在**代码块里的示例标记**处
  > 错误截断。现在两边共用同一份实现，不会再各自漂移。

- 条数

  默认只保留**最新 50 篇**（`VANBLOG_RSS_ITEM_LIMIT`，设 `0` = 不限制）。
  文章很多时这能显著减小 feed 体积；想让老文章也进订阅就调大它或设 0。

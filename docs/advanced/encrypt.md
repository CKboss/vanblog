VanBlog 支持对文章进行加密。加密后，前台的文章将被隐藏，需要输入密码之后才能看到内容。密码会在后端验证，并只有匹配时才会把文章数据返回前端。

![文章详情](https://pic.mereith.com/img/fad60a38e0d6819bfe6089108fe4142a.clipboard-2022-08-16.png)

## 加密方法

- 在创建文章时勾选加密，并输入密码。
- 在编辑器页面点击 `修改信息`，勾选加密并输入密码。
- 在发布草稿时勾选加密并输入密码。

分类也支持同样的访问密码（加密分类下的文章全部上锁），行为一致。

## 密码怎么存的：scrypt 哈希，不可找回

::: danger 忘记访问密码 = 找不回来

文章/分类的访问密码在服务端**只存 scrypt 哈希**（与登录口令同一套参数），任何接口都
**不回显**密码或哈希 —— 后台列表与表单拿到的只是一个「有没有设密码」的布尔（`hasPassword`）。
这是有意的：以前的版本把密码**明文**存在库里（拿到数据库或整站备份 = 拿到所有加密文章的密码），
而哈希是不可逆的，所以**没有任何找回手段**。忘了密码只有一条路：在后台「修改信息」里
显式清除或重设（需要管理员登录态）。

:::

由此带来的表单语义变化（升级后第一次改文章信息时会注意到）：

| 你在表单里的操作 | 结果 |
| --- | --- |
| 密码框**留空**保存 | **不修改**原密码（以前留空可能被理解成清空） |
| 填入新密码保存 | 重设为新密码（写入新哈希） |
| 勾选「清除密码」开关保存 | 解除加密（有二次确认；开关只认显式勾选，不会误清） |

历史数据不需要你动手：启动时有一个**幂等的清洗任务**把库里的明文密码洗成 scrypt 哈希
（洗过的不会二次哈希；整站备份/恢复、JSON 导入导出的往返也不会把哈希当成密码）。
`.mdz` 导入会直接**丢弃** front matter 里的 `password` 字段（明文密码不进新库），
但保留 `private: true`，文章维持加密状态、密码导入后重设。

## 防暴力尝试

- 输密码解锁的接口有**限次**：同一来源 IP + 同一篇文章，10 分钟 20 次，超了要等冷却。
  计数的 key 里文章 id 做了归一化（换一种拼法写同一个 id 不会重置计数），
  IP 用的是[可信客户端 IP](./security.md#认证)（默认 `trusted`）。
- 密码比较是**常量时间**的，不会因短路泄露长度/前缀信息。
- 加密文章的标题与内容不会通过搜索、RSS、sitemap、静态搜索索引、相关文章、
  上一篇/下一篇这些公开面泄露（未到点的定时文章同理）。

相关的安全设计与环境变量见 [安全与加固](./security.md)。

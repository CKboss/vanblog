title: 忘记密码
icon: question
---

忘记**后台管理员**的登录密码时，用「恢复密钥」自救：在登录页点 **忘记密码**，填用户名、新密码与恢复密钥即可重置。

![查看恢复密钥](https://pic.mereith.com/img/471a81dc548ad543814a6bbf7315ccf1.clipboard-2022-09-20.png)

::: warning 用户名要填**当前**的管理员用户名

这个表单里的「用户名」会被**写回账号**：填成别的名字，等于顺手把管理员的用户名也改了（密码同样被改掉）。
所以除非你就是想改名，否则照着现在的用户名填。

另外两条限制：用户名 1–50 个字符、密码 1–200 个字符，**空值会被直接拒绝**（否则密码哈希会被写成空串，
之后任何密码都登不进来，自救工具反而把人锁死）。

:::

重置成功之后：

- **全部 token 被吊销**：所有设备的登录态失效（要用新密码重新登录），**API Token 也一起失效**（见下面第 1 条）；
- **恢复密钥会立刻重新生成**，你手上那条旧的随即作废。

## 恢复密钥在哪里

密钥**每次 VanBlog 启动、以及每次被使用之后都会重新生成**，所以别用旧笔记里的值 —— 现取现用。
三种取法，任选一种（都不用停站）：

### 1. 一键脚本部署：直接看宿主机上的文件（最省事）

```bash
cat /var/vanblog/data/log/restore.key
```

路径是 `<数据目录>/log/restore.key`（数据目录默认 `/var/vanblog/data`，见 [目录映射](../reference/dir.md)）。
文件权限是 `0600`，所以要用 root（或 `sudo cat`）才读得到。

### 2. 从日志里看

启动时会打一条 WARN，内容形如 `忘记密码恢复密钥为： <密钥>`：

```bash
./vanblog.sh log                      # 一键脚本部署
docker logs --tail 200 <容器名> | grep 恢复密钥
```

不知道容器名时先列一下（编排里没有写死 `container_name`，名字随 compose 版本与目录名变化）：

```bash
docker ps --format '{{.Names}}\t{{.Image}}'
```

### 3. 进容器里读文件

```bash
docker exec <容器名> cat /var/log/restore.key
```

::: tip 找不到 restore.key？

- 日志目录没映射出来的话，文件只存在于容器内 —— 用上面第 3 种方式读；
- 站点**已经初始化过**才会有这条流程；如果是全新站点还没装好，那要找的是
  **初始化密钥** `setup.key`（见下一节），不是恢复密钥。

:::

## 别和这两个搞混

- **`setup.key`（初始化密钥）**：同样在日志目录里，但它只服务于**未初始化期间**的
  初始化 / 整站恢复接口（`VANBLOG_INIT_REQUIRE_SETUP_KEY`，默认开启），站点初始化成功后
  就会被自动删除。它救不了忘记的登录密码，见 [初始化 → 初始化密钥](../guide/init.md#初始化密钥setup-key)。
- **文章 / 分类的访问密码**：这类密码只存 scrypt 哈希，**没有任何找回通道**（恢复密钥也救不了它），
  忘了只能登录后台在「修改信息」里显式清除 / 重设，见 [加密文章](../advanced/encrypt.md)。

## 重置之后建议顺手做的两件事

1. **重新签发 API Token**：改密码 / 保存账号信息时服务端会吊销**全部** token —— 不只是浏览器的登录态，
   **`Token 管理` 里签给脚本用的 API Token 也一起失效**，之后调用会 401。到
   **系统设置 / Token 管理** 重新签发一个，并更新你的脚本 / cron，见 [登录安全策略](../reference/secure.md)。
2. 顺手做一次整站备份：`./vanblog.sh backup-verify`（备份 + 立刻校验），见 [备份与迁移](../guide/backup.md)。

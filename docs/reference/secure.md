后台的 **站点管理 / 系统设置 / 高级设置** 里有两项与登录安全直接相关的设置：
「开启最大登录失败次数限制」与「登录凭证(Token)有效期(秒)」。这一页说清它们的默认值、
生效范围，以及凭证什么时候会失效。

## 最大登录失败次数限制

**默认开启**：全新站点（还没有任何登录设置）就带着这道保护，只有在后台显式关掉才会关。

- **默认阈值**：同一个来源 IP 在 **300 秒（5 分钟）**内失败 **5 次**，之后的登录请求会被直接拒绝 ——
  返回 `401` 和一句 `错误次数过多！请 N 秒后再试！`（N 是还要等多少秒），同时日志里记一条 WARN
  （含 IP、当前计数、剩余秒数）。
- **只统计失败**：登录成功会把计数清零，所以「换浏览器重新登录」「登出再登进」这类正常操作
  不会把自己锁在门外。
- 窗口从**第一次失败**开始算，超过 300 秒自动作废重新计数。
- 后台能改的是**开关**；**次数与秒数没有表单字段** —— 代码读的是设置里的 `maxRetryTimes` /
  `durationSeconds`（大于 0 才生效），没设过就用上面的 5 次 / 300 秒。

::: warning 计数按「可信客户端 IP」分桶

一体式部署里 caddy 是从 `127.0.0.1` 拨到 API 的。如果按套接字地址计数，**所有访客共用一个桶** ——
别人失败 5 次就能把带着正确密码的你锁在门外，而且每 5 分钟还能续期，等于后台被永久拒绝服务。

所以默认按「可信客户端 IP」计数：只有对端是回环 / 私网时才采信 `X-Forwarded-For` 的**最右一跳**
（客户端伪造的头会被 caddy 追加在它自己写的 IP 左边，所以既绕不过、也栽赃不了）。

如果你的反代是**覆盖**而不是追加 `X-Forwarded-For`，把 `VANBLOG_BRUTE_FORCE_IP_SOURCE` 设成
`socket`，退回只看套接字地址（更严格，代价是同一出口 IP 的人共用一个桶）。
判定细节见 [环境变量](./env.md#安全限流与可观测性) 与 [反代](./reverse-proxy.md)。

:::

::: note 多进程部署时阈值会按 worker 数摊薄

失败计数存在**每个进程自己的内存**里。开了 `VANBLOG_CLUSTER_WORKERS=N`（默认 1）之后，
同一个 IP 的请求被轮流分到 N 个 worker、每个只看到 1/N，爆破预算就变成 N 倍 ——
所以阈值会按 worker 数除以 N（单进程时除数是 1，值不变）。摊薄是近似的，
但偏差方向是「更严」，对防爆破来说是安全的那一侧。

:::

## 登录凭证(Token)有效期(秒)

这一项就是登录时签发的 JWT 的存活时间：

- **默认 7 天**（604800 秒）。个人博客场景没必要设得很短。
- **最小 60 秒**：这个值会原样进 JWT 的 `expiresIn`，填 0 或负数会让签出来的 token **立刻过期**
  （表现是「登录看着成功，下一个请求就被踢回登录页」），所以表单在这一层就把下限夹住了。
- 改它只影响**之后**签发的凭证，已经发出去的不受影响。

### 凭证什么时候会立刻失效

| 动作 | 影响范围 |
| --- | --- |
| 点「退出登录」 | 只吊销**当前这个** token（其它设备仍然在线） |
| 在「用户设置」里保存账号信息 / **改密码** | 约 1 秒后吊销**全部** token ⇒ 所有设备都要重新登录，**`Token 管理` 里签发的 API Token 也一起失效**（脚本会开始 401，需要重新签发） |
| 用恢复密钥重置密码（忘记密码流程） | 同上：全部吊销（含 API Token），并**重新生成**恢复密钥 |
| 新建 / 修改协作者 | 吊销所有**协作者**的 token（管理员的不受影响） |

所以「改完密码之后别的设备被登出」是预期行为，不是出问题了。

## 密码是怎么存的

- **管理员 / 协作者的登录口令**：存 scrypt 哈希（`N=16384, r=8, p=1`，带随机盐），
  形如 `scrypt$16384$8$1$<salt>$<hash>`。早先的旧格式会在**登录成功时自动升级**成 scrypt，
  不用改密码、也不用停机跑脚本。
- **文章 / 分类的访问密码**：同样只存 scrypt 哈希，任何接口都**不回显**（后台只告诉前端
  「有没有设密码」这个布尔值）。表单语义是「留空 = 不修改」，要解除加密必须显式勾「清除密码」。
  ⚠️ 代价是**忘记访问密码就没有找回通道**（恢复密钥也救不了它），只能在后台清除 / 重设，
  见 [加密文章](../advanced/encrypt.md)。
- **忘记管理员登录密码**：走日志目录里的 `restore.key`，见 [忘记密码](../faq/password.md)。

## API Token 是另一套

后台 **系统设置 / Token 管理** 签发的是给脚本用的 API Token，与上面的登录凭证分开管理：

- 有效期默认 **365 天**，用 `VANBLOG_API_TOKEN_TTL_DAYS` 调（最小 1 天）。早先默认是 100 年，
  等于永不过期 —— 泄露一次就长期有效，还没法靠时间自愈。
- 改默认值不影响已经签出去的 token（各自的有效期在签发时就写进库里了）。
- 可以单独吊销。调用方式是在请求头里带 `token` 字段，见 [API 参考](./api.md#鉴权)。

## 相关的其它限制

- 登录接口（`POST /api/admin/auth/login`）受**全局限流**约束：默认每 IP 每分钟 600 次
  （`VANBLOG_RATE_LIMIT_PER_MIN`）。
- 匿名可写的公开接口（评论、访客统计等）另有一个更紧的桶：默认每 IP 每分钟 **30** 次
  （`VANBLOG_PUBLIC_WRITE_LIMIT_PER_MIN`）。
- 加密文章的**解锁**接口按「同 IP + 同一篇文章」限次：**10 分钟 20 次**，超限返回 `429`
  与「尝试次数过多，请 N 秒后再试」。文章 id 会先归一化，所以 `7`、`0000000007`、`0x7`
  这类写法**共用同一个计数器**，换个写法并不能换来新的 20 次。

全部阈值与开关见 [环境变量 → 安全、限流与可观测性](./env.md#安全限流与可观测性)；
反代 / CDN 场景下的 IP 判定见 [反代](./reverse-proxy.md)；这一轮修掉的安全问题清单见
[安全与加固](../advanced/security.md)。

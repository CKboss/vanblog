VanBlog 可以配置一系列的站点配置项，可在 `站点管理/系统设置` 中查看。

包括三类：

- 基本设置：博客系统正常运行必须的配置
- 高级设置：博客系统的进阶选项
- 布局设置：改变前台展示布局的设置（含**界面风格**、每页文章数、分类页默认展开、友链页 / 关于页文案、导航栏左侧显示网站名或 logo）。手机端顶栏网站名相对整页宽度居中，电脑端仍在左侧。前台首页和 `/page/n` 分页在多页时可以输入页码跳转；非法或超出范围的数字不会跳转。总页数跟随「每页文章数」。

![站点设置](https://pic.mereith.com/img/abb9afde6ccf1ee82cfe41e083df4daf.clipboard-2022-08-15.png)

所有设置项详见 [参考 → 站点配置](../reference/config.md)。

## 主题与界面风格

`界面风格` 决定前台用哪个主题：内置的 `Apple 风格`（默认）与 `默认（原卡片风格）`，
以及你在 `系统设置 → 主题` 里上传的**自定义主题**。主题就是一份 CSS，上传后点「启用」，
前台刷新即生效（不用重新构建、不用重启容器）。写法、可用的稳定钩子、限制与示例主题见
[主题（前台皮肤）](./theme.md)。

## 界面风格（Apple 风格）

`站点管理 / 系统设置 / 站点配置 / 布局设置 → 界面风格` 可以切换前台的视觉语言：

| 选项 | 说明 |
| --- | --- |
| **Apple 风格**（默认） | 参考 [Apple Developer News](https://developer.apple.com/news/) 的排版：SF Pro 字体栈、17px 正文、单列发丝线分隔的列表、毛玻璃导航栏、苹果蓝强调色、胶囊按钮、18px 圆角卡片 |
| 默认 | VanBlog 原本的卡片式外观（一张张带阴影的白卡） |

### 一键给历史文章补封面

老文章大多没设封面（本站 53 篇里原本 **0 篇**有封面），列表页因此几乎没有图。
后台 **文章管理 → 「从正文首图补封面」** 可以一次性回填：

- **先预览再写入**：打开弹窗会先跑一次 `dryRun`，列出「哪些文章会写入哪张图」，可以逐篇取消勾选；
- **只补空的**：默认只处理 `cover` 为空的文章，已有封面的一律不动（也可以显式要求覆盖）；
- **取图规则与前台一致**：文档顺序里的第一张可用图，**优先本站图床**（外链首图随时可能失效，
  还会把访客 IP/Referer 泄露给第三方），只有整篇都没有本地图时才用外链；代码块与行内代码里的
  图片语法会被跳过，`data:` 与相对路径一律不要；
- **可撤销**：写入成功后弹窗会给出「撤销本次改动」，把 `cover` 精确写回旧值
  （用户后来手动改过的不会被覆盖）；
- 写完会触发一次增量渲染，前台不用等下一轮 ISR。

对应的接口（管理员鉴权，演示站禁用）：

```
POST /api/admin/article/covers/from-content   # { dryRun?, onlyMissing?, ids? }
POST /api/admin/article/covers/revert         # { items: [{ id, cover }] }
```

本站实测：53 篇里 16 篇能从正文找到可用首图（另外 37 篇正文根本没有图片），
回填后再跑一次是 0 写入 / 16 跳过（幂等）。

::: tip 顺带的好处

封面字段还喂着另外两处：**文章页的 LCP 预加载**（`<link rel="preload" as="image">`）
和 **`og:image` / `twitter:image`**。所以补完封面之后，这些文章分享到微信、飞书、
知乎、Twitter 时会带上预览图 —— 以前没有封面就是一片空白。

:::

切换只影响**样式**，不改任何页面结构，也不影响你自己写的自定义 CSS（`启用定制化` 里的内容仍然生效，需要覆盖时它的优先级更高）。随时可以切回来。

Apple 风格具体做了这些事：

- **导航栏**：`saturate(180%) blur(20px)` 毛玻璃 + 底部发丝线，高度 52px，链接 14px 灰字、hover 变深。
- **首页/分类/标签列表**：单列 980px，**条目之间用发丝线分隔**而不是浮起的卡片；标题 28px/600 左对齐（hover 变蓝），下面一行 13px 灰色元信息（日期 · 分类 · 阅读数），摘要 17px/1.6 最多露 4 行，「阅读全文」变成蓝色文字链接带 `›`。
- **作者卡片**：从右侧栏移到**页首简介条**（Apple News 没有侧栏），头像 56px、名字与简介横排。
- **文章详情页**：780px 阅读栏，标题 40px/600，元信息行下一道发丝线；标题层级用**字重**区分（h2 28px、h3 22px）；引用块做成浅灰圆角 callout（2px 灰色左边条）；代码块浅灰填充 + 12px 圆角、**不描边**；表格只留行间发丝线（无外框、无斑马纹）；目录（TOC）留在右侧 220px 细栏、当前项蓝色。
- **列表页不再只有黑白灰**：Apple 的排版确实是中性色为主，但它从来不是**只有**中性色 ——
  Apple News 的列表有封面图，标签/徽章用低饱和彩色胶囊，页面顶部常有柔和渐变。所以补了三样：
  - **没有配图的文章就是纯文字卡，不放假图**。曾经试过按标题哈希生成「渐变占位封面」，
    但那个设计是错的，已经删掉：哈希出来的颜色**不承载任何信息**（同分类的两篇会得到毫无关系的颜色），
    一屏五种高饱和色只会让页面变花；而且一个 16:10 带圆角阴影的色块在视觉语法上就是
    「这里有张缩略图」，等于对读者撒谎。Apple News 对没有配图的文章就是纯文字卡，
    节奏靠字号 / 字重 / 留白 / 发丝线，不靠装饰。
    正确的解法是让文章**有真图** —— 见下面的「一键补封面」。
  - **列表缩略图**：`cover` 优先，没设 cover 就取**正文首图**（很多站点一篇文章都没设封面，
    列表页于是只剩文字）。本站图床的图自动换成 300px 缩略图，取不到再回退原图，
    都失败就整块不渲染（绝不留破图标或空框）。桌面端「文字左、图右」浮动排版，
    窄屏时图排在标题上方（与 Apple News 移动端一致），hover 轻微放大 + 阴影加深。
  - **标签彩色胶囊**：色相由标签名哈希得到（同名标签永远同色），低饱和底色 + 同色相深字，
    深色模式另有一套。最多显示 3 个。
  - **页首作者条**：从「透明 + 发丝线」换成两层柔和的径向渐变面板（蓝 + 品红，各 8~10% 不透明度）
    + 18px 圆角，头像加一圈强调色描边 —— 给页面一个色彩锚点。
  - 另外把元信息行的**图标**染成强调色（文字仍是灰的）：只加一点点颜色，不喧宾夺主。
  这些都只在 Apple 皮肤下显示；默认皮肤的 DOM 里虽然有这两个节点，但 CSS 里是 `display: none`，
  版面完全不变。

- **深色模式的层次**：暗色令牌原来是「反的」—— `--ap-surface-2`(#161617) 比
  `--ap-surface`(#1d1d1f) 还**暗**，本该凸起的面看起来是凹下去的，所以整个暗色页面很平。
  现在按 Apple 的暗色系统改成单调递增：`canvas #000 < surface #1c1c1e < surface-2 #2c2c2e < surface-3 #3a3a3c`，
  并且因为**纯黑底上的投影几乎看不见**，改用两道光学信号来表达"抬升"：
  `--ap-inset-highlight`（顶边 1px 高光，模拟从上方打的光）+ `--ap-ring`（1px 半透明环，把面从背景里勾出来）；
  浮层（搜索面板 / 下拉 / 气泡）在此之上再加一层投影，拉开"离地高度"。
  发丝线从实色 `#424245` 改成半透明白 `rgba(255,255,255,.16)`（实色在黑底上太重，会把版面切成一块块），
  列表条目之间的分隔线在深色下再淡一档；代码块 / 引用块 / 表头各抬一层表面色；
  正文图片加一道极淡的环，避免在纯黑底上"糊成一片"。
- **不用线框**：Apple 的层次靠**留白 + 发丝线 + 浅灰填充**，不靠描边。所以文章卡、作者卡、导航、分页、输入框、代码块、提示容器全部**无描边**；需要边界感的地方（友链卡片、正文里的提醒/版权/打赏小块）用 `#f5f5f7` 浅灰填充 + 圆角。整份皮肤里只剩这几处单边发丝线：导航底部、列表条目之间、文章元信息下、引用块左边、表格行之间、页脚上方、搜索面板输入行下方。
- **标题右侧的「编辑」和复制按钮**压成 13px 次要灰、常规字重（组件里原本是近黑 `text-dark`，在 Apple 排版里太重），hover 才变蓝。
- **时间线**：年份 32px/600，竖轨改成发丝线，条目 hover 变蓝；月份行的展开按钮是 22px 正圆浅灰底、`>` 用 flex 居中（组件原本是 `inline-block` + 内联宽度 + `text-lg`，直接加圆角和内边距会让箭头偏心）。
- **元信息行**（标题下的 时间 / 分类 / 阅读量 / 评论量）：去掉 Tailwind `divide-x` 画的竖线，只留 18px 间距 —— Apple 的元信息行不画分隔线。
- **关于页**：和文章页一样套 `.vanblog-article-page` 作用域（780px 阅读栏、40px 标题、正文不被列表页的「摘要 4 行」规则裁掉）。摘要截断现在只作用于**带「阅读全文」按钮的列表卡**。
- **字体**：Apple 风格下全站用 **Maple Mono**（中文 / Nerd Font 子集是 `Maple Mono NF CN`），两条来源分开看：

  - **拉丁子集已经自托管**（不再走第三方 CDN）：文件是
    `packages/website/public/fonts/maple-mono-latin-400-normal.woff2`（74 KB，取自
    `@fontsource/maple-mono@5.3.0`，与 jsDelivr 上那一份逐字节一致，SHA-256 与许可证都由测试钉住），
    `@font-face` 声明在 `styles/apple.css` 里，`font-display: swap`。首屏由 `components/Layout`
    输出**一条** `<link rel="preload">`（只在皮肤开启时），让字体下载与阻塞式 CSS 解析并行。
    换掉 CDN 的三个理由：自托管博客不该靠别人家 CDN 出首屏字体、`@latest` 会漂移、少一条跨域连接。
    ⇒ 前台代码现在**不向任何第三方字体域名请求一个字节**。
  - **中文 / Nerd Font 子集仍走远程**：zeoseven 的字体 CSS（地址在 `utils/appleFont.ts` 的
    `APPLE_FONT_CSS_URL`）。它里面是**按 unicode-range 切好的几十上百个分包**，所以没法自己写一个
    `@font-face` 顶掉。这一份是**非阻塞**加载的（`media="print"` 取完再翻成 `all`），
    并配了 `preconnect` / `dns-prefetch` 提前建连和 `<noscript>` 兜底（关掉 JS 时没有水合）；
    解析不了或加载不上时，退回自托管的拉丁子集与系统字体栈 —— 最坏情况只是中文用系统字体，页面照常渲染。

  ::: warning 为什么必须异步

  普通的 `<link rel="stylesheet">` 是**渲染阻塞**的。而这个字体域名在部分网络下解析不了
  （实测有机器上 `static.zeoseven.com` DNS 失败，而 `zeoseven.com` 本身是通的）——
  阻塞加载会让首屏一直白屏等到浏览器超时。异步加载之后，最坏情况只是**用兜底字体**，
  页面照常渲染。

  :::

  三个实现细节值得知道：

  1. 字体是写在**令牌**里的（`--ap-font` / `--ap-font-mono`），Maple Mono 打头，
     后面完整保留原来的 SF Pro / 苹方 / 微软雅黑栈。所以远程字体加载不上（离线、CDN 不可达、
     装了拦截插件）时会优雅退回系统字体，不会出现「正文变成浏览器默认衬线体」这种事故；
     代码块走 `--ap-font-mono`，也不会被正文字体覆盖。
  2. 字体挂在皮肤根节点（`[data-ui="apple"]`、`[data-ui="apple"] body`）上靠**继承**生效，
     不需要 `p, span, div { font-family: … }` 那种宽选择器 —— 宽选择器会把代码块的 mono 令牌
     和第三方组件（评论区、播放器）一起覆盖掉。
  3. 翻 `media` 靠的是那个 `useEffect`，**不是** `<link>` 上的 `onLoad`：`next/head` 是用
     `document.createElement` + `setAttribute` 把子元素搬进 `<head>` 的，函数类型的 prop 不会被带过去；
     而且命中缓存时可能在监听挂上之前就加载完了。`onLoad` 只是锦上添花。

  开启 Apple 风格时，**后台编辑器的预览面板**也会用同一套字体（只影响预览，不动左侧编辑区和后台其它页面），
  详见 [编辑器](editor.md)。换字体源要同时改两处：前台 `packages/website/utils/appleFont.ts`
  与后台 `packages/admin/src/components/Editor/useApplePreviewFont.ts`（有测试盯着一致性）。
  ⚠️ 两边有一处**故意的不同**：后台预览的拉丁子集仍从 jsDelivr 取（版本钉死 `@5.3.0`，与前台自托管那份同版本）。
  理由是后台属于登录后的界面、不在读者的关键路径上，把同一个 74 KB 字体再复制进第二个包换不来可测量的收益，
  反而多一份会和前台漂移的副本；CDN 不可达时后台只是预览面板退回系统字体。

  ::: tip 想换字体 / 自己托管

  - 换字体：改 `styles/apple.css` 里 `--ap-font` 与 `--ap-font-mono` 的开头几项即可，
    想完全回到系统字体就把 `"Maple Mono NF CN", "Maple Mono",` 删掉。
  - 换成别的字体源：改 `utils/appleFont.ts` 里的 `APPLE_FONT_CSS_URL`（就一处，
    preconnect 的域名列表 `APPLE_FONT_PRECONNECT_HOSTS` 也在那里）。
  - **自己托管**（不依赖任何第三方 CDN，也顺带绕开 DNS 不可达的风险）：
    从 [maple-font 的 GitHub Releases](https://github.com/subframe7536/maple-font/releases)
    下载 NF-CN 变体，放进 `packages/website/public/fonts/`，在 `apple.css` 里按 **unicode-range 分包**
    声明 `@font-face`（中文务必分包，否则单文件十几 MB 会拖慢首屏；npm 上没有现成的
    `maple-mono-nf-cn` 包，仓库里也只有 Release 产物），然后把 `APPLE_FONT_CSS_URL` 设成 `null`
    —— 代码里已经支持：为 `null` 时那个 `<link>` 和 preconnect 都不会输出。
  - 想完全用系统字体：把 `--ap-font` / `--ap-font-mono` 开头的
    `"Maple Mono NF CN", "Maple Mono",` 删掉，并把 `APPLE_FONT_CSS_URL` 设为 `null`。

  :::

  ::: warning 不要用 @import 引远程字体样式表

  CSS 规范要求 `@import` 必须位于样式表**所有其它规则之前**。而 `apple.css` 是被 `globals.css`
  用 `@import` 内联进来的（它前面还有 `siteNameLayout.css` 和 Tailwind 产物），
  内联之后远程 `@import` 就不再处于首位 → 浏览器会**静默丢弃**它：字体加载不上，控制台也不报错。
  所以远程那份走 `<link>`。仓库里有测试盯着这条（样式文件里不允许出现远程 `@import`）。

  :::
- **分类/标签**：胶囊 chip，浅灰底、选中/hover 蓝底白字。
- **分页**：无描边的安静文字，hover 浅灰胶囊，当前页浅灰填充 + 半粗。
- **友链卡片**：`#f5f5f7` 浅灰填充 + 18px 圆角、无描边，hover 只抬升 2px（原来是 -8px，太跳）。
- **搜索浮层（右上角放大镜 / `Ctrl`+`K`）**：半透明黑遮罩 + 8px 背景模糊；面板是白色 sheet（18px 圆角 + 大投影，暗色 `#1d1d1f`）；输入框 21px 无框、下面一道发丝线；结果行去掉虚线，改成圆角行 + hover 浅灰；`Ctrl K` / `Esc` 快捷键提示改成无边框浅灰小胶囊。
  > 覆盖层（sheet / 弹窗）**必须**有表面和投影，这不属于「不用线框」的范围。
- **页脚**：发丝线上边框 + 13px 灰字。
- **暗色模式**：整套令牌反转（画布 `#000`、表面 `#1d1d1f`、强调色 `#2997ff`），图片自动降到 `brightness(.92)`，跟 Apple 官网一致。
- **移动端**：字号收一档（标题 22px、正文 16px），目录栏隐藏，简介条收紧。

::: tip 实现方式

所有规则都挂在 `[data-ui="apple"]` 选择器下，由 `components/Layout` 按站点设置输出到最外层容器（并同步到 `<html>`），所以它是一层**可整体开关的皮肤**，不会污染默认风格的样式，也不会和你的自定义 CSS 打架。

`packages/website/__tests__/appleTheme.spec.ts` 里有一组守卫测试：任何选择器逃出 `[data-ui="apple"]` 作用域、或者皮肤里出现了四面包围的描边（`border: 1px solid …`），测试就会红。

:::
